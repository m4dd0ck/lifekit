# Lifekit

Local-first personal management CLI: habit tracking, journaling, goals. Python, Typer, DuckDB.

This file is the reference: what exists and how it works. `RUNBOOK.md` is the procedures,
`CLAUDE.md` the agent rules, `TASK.md` the open items.

## What it is

One command, `lk`, over one DuckDB file. Habits carry a reason and a tiny version, journal
entries carry mood, energy and gratitude, goals carry milestones and a progress figure, and the
analytics read across all three. An optional weekly narrative is written by the Anthropic API
when asked for; nothing else leaves the machine.

## Why it exists

A habit tracker with no punishment mechanics (a missed habit is simply not logged) whose journal
and habits can be read against each other, built as a portfolio piece to show an append-only
event store on DuckDB behind a Typer CLI. The ideas and the research behind the data model are in
`BRAINSTORM.md`; the build spec is `PRPs/lifekit-mvp.md`.

## Quick start

```bash
uv sync
uv run lk habit add "Morning run" --why "Energy for the day" --tiny "Put on shoes"
uv run lk habit log "Morning run" --mood 4 --energy 3
uv run lk stats
```

Options by example:

```bash
# Habits
lk habit add "Morning run" --why "Energy for the day" --tiny "Put on shoes" --desc "3k loop"
lk habit log "Morning run" --mood 4 --energy 3 --difficulty 2 --quality 4 --context "Rainy"
lk habit list              # --archived / -a to include archived habits
lk habit stats "Morning run"
lk habit archive "Morning run"

# Journal
lk journal write "Had a productive day" --mood 8 --energy 4 --gratitude "Good weather"
lk journal list            # --limit / -n, default 10
lk journal prompt          # --category / -c (gratitude, reflection, shadow, goal)
lk journal search "productive"

# Goals
lk goal add "Run a 5k" --deadline 2026-04-01
lk goal milestone "Run a 5k" "Run 1 mile without stopping"
lk goal progress "Run a 5k" 40
lk goal list               # --status / -s (active, achieved, abandoned)

# Analytics
lk stats                   # overview
lk stats mood --days 14    # default 7
lk stats habits
lk stats correlations

# AI (requires ANTHROPIC_API_KEY)
lk narrative --days 7

# Sealed letters
lk letter "Morning run"

# Maintenance
lk rebuild                 # reconstruct the state tables from the event log
```

Habit `--mood`, `--energy`, `--difficulty` and `--quality` take 1-5. Journal `--mood` takes
1-10 and `--energy` 1-5. Goal progress is 0-100; reaching 100 marks the goal achieved.

## How it works

**Storage.** Every change is written to an append-only `events` table and then applied to plain
current-state tables (`habits`, `habit_logs`, `journal_entries`, `goals`, `milestones`) in the
same DuckDB file. The event log is the record of what happened; the tables are what the CLI
reads. `lk rebuild` empties the state tables and replays the whole log through the same
per-event projection, in one transaction, so the tables can always be reconstructed from the
log; it prints the row count of each table afterwards. `storage/database.py` owns the schema,
the projection and the rebuild; `storage/events.py` exposes one method per command. A new
database is seeded with the default journal prompts (`prompts`) in four categories; prompts are
seeded, not event-sourced, and `rebuild` leaves them alone.

**Names.** Commands refer to habits by name and to goals by outcome. The match is exact (any
case for goals) and only active habits and goals count, so `habit add` refuses a name an active
habit already has, `goal add` refuses an outcome an active goal already has, and an archived
or finished name can be reused. A name that matches nothing, or more than one row in a
database written before this rule, is reported as an error.

**Analytics.** `streaks` gives the current and longest streak and the completion rate since the
habit was created. `trends` gives per-day mood and completion series. `correlations` compares
average journal mood on days a habit was done against days it was not (a difference of means,
not a coefficient), and `chronotype_analysis` counts completions by hour. Habits with fewer than
three days of data are left out of `stats correlations`.

**Narrative.** `lk narrative` formats the habit logs and journal entries of the last `--days`
calendar days (the same window as `stats mood`) into a prompt and asks the model named in
`src/lifekit/ai/narrative.py` for a short story of the week. It needs `ANTHROPIC_API_KEY` in
the environment and prints a message instead of failing when the key is missing. The token
budget leaves room for a thinking block before the text.

**Models and validation.** `models/` holds the Pydantic models for events, habits, journal
entries and goals. The store builds the model for every write, so an out-of-range rating, an
empty name or a progress outside 0-100 is rejected with a one-line `InvalidValueError` before
any event is appended; the CLI prints that line (`Error: mood_after: Input should be less than
or equal to 5`) and exits 1. Typer checks the same ranges at the flag level, so most bad input
never reaches the store. `errors.py` holds the exception hierarchy under `LifekitError`.

## Vocabulary

**Tiny version.** The two-minute form of a habit (`--tiny`), the thing to do on a bad day.

**Why.** The reason given at `habit add`; `lk letter` reads it back as a sealed letter to the
future self.

**Archive.** A habit no longer tracked. Archived habits keep their logs and show with
`habit list --archived`.

**Event and current state.** An event is the immutable record of one change; the current-state
tables are its projection, updated once as the event is appended and rebuilt from the whole log
by `lk rebuild`.

## Decisions

- **2026-01-28** DuckDB rather than SQLite, and events projected inline as they are appended
  rather than replayed: the analytics are read-heavy and one file is enough.
- **2026-10-07** `-d` is the short flag of `--db-path` only; `--deadline` and `--days` lost
  theirs because Click let one option silently win when two shared it.
- **2026-10-07** The README documents every command, including `habit archive`, `journal list`
  and `goal list`, and says the event log is not replayed.
- **2026-10-17** The narrative's token budget was raised so a thinking block does not crowd out
  the text.
- **2026-10-17** CI comes from the owner's shared workflow template.
- **2026-10-28** The store validates every write by building its Pydantic model, rather than
  trusting the CLI: the models already carried the ranges, and a second caller (tests, a future
  UI) would otherwise write anything.
- **2026-10-28** `lk rebuild` replays the event log into the state tables. Inline projection
  stays the normal path (2026-01-28); the rebuild exists so the log, not the tables, is the
  copy that matters.
- **2026-10-28** Goal lookup is exact among active goals, not a `%x%` match over all of them:
  a substring picked an arbitrary goal when several matched, and habits already worked this
  way. Duplicate active names are refused at creation so the lookup cannot be ambiguous.
